# 슬라이드 수정 터미널로 발표자료 만들기

발표자료를 HTML 슬라이드로 만들고, 사용자는 **수정 터미널**에서 고칠 부분을 마우스로 드래그해 요청을 남긴다. Claude는 그 요청을 받아 덱을 고치고, 측정으로 확인한 뒤 다시 게시한다. 이 왕복을 수십 번 반복해 완성도를 올리는 것이 핵심이다. 사용자가 말로 설명하기 어려운 "여기 이 부분"을 좌표와 실제 글자로 정확히 전달받을 수 있어서, 고칠 곳을 잘못 짚는 일이 줄어든다.

## 구성 파일

```
slide-terminal/
├── scripts/build.ps1        덱 · 로컬 터미널 · 아티팩트를 한 번에 조립
├── scripts/new-project.ps1  새 덱 프로젝트 폴더 만들기
├── scripts/serve.ps1        점검용 로컬 서버 (브라우저 창에서 측정할 때)
├── assets/term.html         수정 터미널 UI (자리표시자 {{TERM_TITLE}} 등)
├── assets/deck_shell.html   발표용 껍데기 (키보드·휠·스와이프·#쪽번호)
├── assets/viewport-base.css 1920×1080 무대 기본
├── assets/starter/          출발용 slides.html · deck.json · img/ci.png
├── examples/bp-v2/          실제로 88건 수정을 거친 덱(deck.css, slides.html) — 컴포넌트 예시
└── references/
    ├── style-rules.md       사용자가 정한 문체·디자인 규칙과 기관 팔레트 (덱을 쓰기 전에 읽기)
    ├── review-loop.md       요청 받기 → 반영 → 검증 → 재게시 한 바퀴의 상세 절차
    └── verify.md            브라우저에서 돌리는 측정 스크립트(넘침, 정렬, 팔레트)
```

## 프로젝트 폴더 (작업 원본)

한 덱은 한 폴더에 둔다. 원본은 scratchpad 같은 작업 폴더에 두고, 결과물만 사용자 폴더에 쓴다.

```
<작업폴더>/
├── slides.html   <section class="slide" data-title="…"> 만 나열 (head/body 없음)
├── deck.css      k- 접두사 컴포넌트와 .slide{--k-…} 색 토큰
├── deck.json     제목·터미널 부제·저장 키 (아래)
├── img/          ci.png, photo.png … → slides.html에서 {{ci}}, {{photo}}로 참조
└── art/          게시용 아티팩트 html
```

`deck.json` 키: `deckTitle`(발표 창 제목), `termTitle`, `termSub`(터미널 머리글), `deckLabel`(지시문에 찍힐 덱 경로), `short`(빈칸 목록 머리), `key`(브라우저 저장 키, 덱마다 다르게).

모든 컴포넌트 클래스가 `k-`로 시작하는 이유: 같은 슬라이드 DOM을 터미널 안에 복제해 넣기 때문에 터미널 UI 클래스와 부딪히면 안 된다. 색도 `:root`가 아닌 `.slide{}`에 토큰으로 둔다.

## 처음 만들 때

1. **내용부터 합의한다.** 공고문·평가기준·기존 자료가 있으면 먼저 읽고, 목차와 쪽별 요약을 코드블록으로 보여 준 뒤 사용자 확인을 받는다. 쪽수 상한(예: 15쪽)과 대제목 구성을 사용자가 정하면 그대로 따른다. 이 단계에서 슬라이드를 만들지 않는다 — 구조가 바뀌면 만든 것을 다 버리게 된다.
2. `references/style-rules.md`를 읽는다.
3. 프로젝트 폴더를 만든다.
   ```powershell
   & "<스킬경로>\scripts\new-project.ps1" -Dir "<작업폴더>"
   ```
   `deck.css`는 검증된 디자인 시스템(examples/bp-v2)을 그대로 가져온다. 기관이 다르면 색 토큰만 바꾼다. 새 쪽 형식이 필요하면 `examples/bp-v2/slides.html`에서 비슷한 쪽(대시보드 표, 기존→현재 비교, KPI 카드, 다이어그램 3단, 간지, 감사합니다)을 찾아 고쳐 쓴다.
4. `slides.html`을 쓴다. 아직 모르는 숫자·사실은 지어내지 말고 `<span class="tbd">○○</span>`로 비워 둔다. 터미널이 이것을 세어 「빈칸·필요 자료」 탭에 모아 주므로 사용자가 담당자에게 자료를 요청할 수 있다.
5. 빌드하고 측정한다(`references/verify.md`). 넘침·제목 두 줄·열 끝 어긋남이 없을 때까지 고친다.
6. 사용자 폴더에 덱과 로컬 터미널을 쓰고, 아티팩트를 게시한다.
   ```powershell
   & "<스킬경로>\scripts\build.ps1" -Dir "<작업폴더>" -DeckOut "<사용자폴더>\발표_슬라이드.html" -TermOut "<사용자폴더>\발표_수정터미널.html" -ArtOut "<작업폴더>\art\terminal.html"
   ```
   아티팩트는 `db` 기능을 선언해 게시한다(artifact-capabilities 스킬을 먼저 불러온다). 그래야 사용자가 터미널에 저장한 요청을 Claude가 `ArtifactData`로 바로 읽는다(컬렉션 `requests`). 로컬 HTML 터미널은 브라우저에만 저장되므로 「지시문 복사」로 채팅에 붙여 넣는 방식이 된다.

## 수정 요청이 오면

요청은 두 경로로 온다: 채팅에 붙여 넣은 `[슬라이드 수정 요청] … ■ R12 · 4쪽 「…」 …` 글, 또는 "수정 요청 반영해줘"(→ 아티팩트 db의 `requests`에서 상태가 `요청`인 것을 읽는다). 절차는 `references/review-loop.md`에 있다. 요점:

- 각 요청의 **영역 좌표 + 현재 글자 + 수정 내용 + 함께 챙길 것**을 함께 본다. "같은 표현을 다른 슬라이드에도"가 체크돼 있으면 덱 전체를 검색해 같이 고친다.
- 요청이 여러 건이고 사용자가 하위 에이전트 위임을 원하면 위임한다. 한두 줄 고치는 작은 요청은 직접 한다.
- 고친 뒤 반드시 빌드 → 측정 → 스크린샷으로 확인하고 나서 재게시한다. 같은 파일 경로로 다시 게시하면 같은 URL이 갱신된다.
- db로 받은 요청은 반영 후 `status:'수정완료'`, `doneAt`, 짧은 `reply`를 써 둔다. 사용자는 완료된 것을 화면에서 숨겨 본다.
- 해석이 갈리거나 사용자가 결정할 일은 고치지 말고 `reply`나 답변에 질문으로 남긴다.

## 터미널 기능 (사용자에게 설명할 때)

- 왼쪽 레일: 쪽 목록, 쪽마다 빈칸 수·열린 요청 수.
- 가운데: 실제 HTML 슬라이드. 드래그하면 영역 안 글자를 자동으로 읽어 「지금 적힌 내용」에 채운다.
- 오른쪽: 수정 유형, 바꿀 내용, 이유, 함께 챙길 것, 우선순위(필수·권장·선택), 메모.
- 상태: 수정 요청 / 수정 완료 / 보류 / 반려 / Claude 제안. 처리한 건은 「완료」 버튼 — 삭제는 잘못 적은 것만.
- 탭: 전체 목록(필터·일괄 지시문 복사), 빈칸·필요 자료(자료 요청 목록 복사).

## 작업 환경 주의 (Windows PowerShell 5.1)

- BOM 없는 .ps1 안에 한글을 넣으면 깨진다. 스크립트는 영어로만 쓰고, 한글은 JSON이나 HTML 파일에 두고 Edit 도구로 고친다.
- `&&` 대신 `; if ($?) { … }`. 함수 이름을 `R`처럼 기본 별칭과 겹치게 짓지 않는다.
- 덱 HTML은 이미지가 data URI로 들어가 수 MB가 된다. 정규식으로 deck.css나 slides.html을 통째로 치환하지 말고 Edit로 정확한 문자열을 바꾼다(한 번에 수백 곳이 망가진 적이 있다). 크게 고치기 전에는 `slides.html.rN.bak`으로 백업한다.
- 사진은 원본 해상도를 그대로 쓰고 재압축하지 않는다. 원본보다 크게 키우면 깨져 보인다.
