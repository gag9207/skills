# Formalize Report Skill

대외 제출 문서(신청서·보고서·제안서)를 **표준 서식으로 작성**하고 **공문서 문어체로 정규화**한다.
정규화는 정규식 일괄 치환이 아니라 **스캔으로 후보를 찾고 사람이 규칙을 확정한 뒤 적용**하는 절차이며,
치환하면 안 되는 구간(인용문·코드·서식 원문)을 반드시 가려 두고 작업한다.

## When this skill activates

- 대외 제출용 보고서·신청서·제안서를 새로 작성할 때 → 먼저 **서식 템플릿**을 복사한다
- 이미 작성한 문서의 구어체 제거, 문어체 전환, 공문서 어투를 지시받았을 때
- 제목을 문장형으로 통일하라는 지시를 받았을 때
- 여러 문서에 걸쳐 서식과 어투를 통일해야 할 때

## 보고서 서식

`references/report-template.html` 이 이 프로젝트의 표준 서식이다.
새 보고서는 이 파일을 대상 경로로 복사한 뒤 내용만 갈아 끼운다. **CSS 는 수정하지 않는다.**
여러 문서를 나란히 놓았을 때 같은 서식으로 보여야 하기 때문이다.

서식이 제공하는 것은 다음과 같다.

| 구성요소 | 클래스 | 언제 쓰는가 |
|---|---|---|
| 좌측 고정 목차 | `nav.toc` | 항상. 화면이 좁으면 본문 위로 접힌다 |
| 본문 아웃라인 | `ul.outline` | 항상. 절 아래의 모든 내용은 이 목록 안에 들어간다 |
| 작성 요령 인용 | `.guide` | **주최 측 서식이 절마다 요령을 정해 두고 그 원문을 그대로 실어야 하는 경우에만.** 내부 기획·정의 문서에는 넣지 않는다 |
| 수치 카드 | `.kpi` | 핵심 수치 서너 개를 먼저 보여 줄 때 |
| 표 | `.tablebox` + `table` | 항목이 셋 이상이고 축이 둘일 때 |
| 도식(단순) | `.flow` | 한 방향으로만 흐르는 단계. 고정폭 글자 그림 |
| 도식(구조) | `.fig` + SVG | 갈라지거나 되돌아오는 구조. **한글 폭 때문에 `.flow` 로는 정렬이 깨진다** |
| 간트 차트 | `.gantt` | 일정을 월별·단계별로 보여 줄 때 |
| 주의 상자 | `.note` | 오해할 수 있는 지점, 미충족 항목. **제목을 상단 칸에 따로 두고 본문을 아래에 둔다** |
| 요점 상자 | `.key` | 절의 결론 하나. 한 절에 둘 이상 쓰지 않는다 |
| 자리표시자 | `.fill` | 작성자가 채워야 하는 곳. **지어내어 채우지 않는다** |
| 캡션 | `.cap` | 표·카드 아래 측정 일자와 조건. 캡션 없는 수치는 쓰지 않는다 |
| 인쇄 규칙 | `@media print` | 항상. 목차를 숨기고 표 잘림·쪽 넘김·배경색을 바로잡는다 |

### 주의 상자의 구조

`.note` 는 바깥 테두리를 사방으로 두르고, **제목 칸을 그 위쪽 테두리에 걸쳐 놓는다.**
제목 칸이 불투명한 배경을 가지므로 테두리가 제목 뒤에서 끊기고 양옆으로 이어진다(`<fieldset>` 의 `<legend>` 와 같은 모양).
제목 칸을 상자 안쪽에 넣지 않는다. 제목을 본문 첫 문장에 붙여 쓰지도 않는다.

걸치게 하는 방법은 **절대 위치**이다. 상자에 `position:relative`, 제목에 `position:absolute; top:-15px; left:20px`
를 주어 제 높이의 절반만큼 테두리 위로 올린다. 제목이 흐름에서 빠지므로 상자의 위쪽 안여백을 26px 정도로 두어
본문이 제목 아래에서 시작하게 하고, 위쪽 바깥여백은 44px 로 늘려 윗 문단과 겹치지 않게 한다.
**이 여백을 다른 규칙이 덮어쓰지 않는지 확인한다.** 목록 안의 블록 요소를 `ul.outline .tablebox, .fig, .flow, .kpi` 처럼
묶어 좁은 여백을 주는 규칙에 `.note` 를 함께 넣으면, 선택자 우선순위가 높아 `.note` 의 값이 무시된다.
제목 칸이 15px 위로 나가 있으므로 여백이 좁아지면 제목이 윗 요소를 침범한다(2026-08-19 실측: 겹침 3px). `.note` 는 그 묶음에서 제외한다.

**인라인 요소에 음수 위쪽 여백을 주는 방법은 쓰지 않는다.** 세로 여백이 줄 상자 계산에 흡수되어 실제로는
올라가지 않는다(2026-08-19 실측: 걸침 0퍼센트). 고친 뒤에는 반드시 브라우저에서 좌표를 재어 확인한다.

색은 다음과 같이 정한다. 색상값을 직접 적지 않고 팔레트 변수로만 지정하여 어두운 화면에서도 관계가 유지되게 한다.

| 부분 | 값 | 의도 |
|---|---|---|
| 바깥 상자 채움 | `var(--card)` | 본문 바탕과 구별되는 옅은 면 |
| 바깥 상자 테두리 | `1px solid var(--line)` | 존재만 알리는 옅은 선 |
| 제목 칸 채움 | `color-mix(in srgb, var(--accent) 12%, var(--bg))` | 도식의 `.box-term` 과 같은 값. 문서 전체가 한 색 체계로 묶인다 |
| 제목 칸 테두리 | 없음 | 채움만으로 구분한다. 테두리를 두르면 바깥 상자 선과 겹쳐 지저분해진다 |
| 제목 글자 | `var(--fg)`, `font-weight:750`, `letter-spacing:0.5px` | 좁은 칸에서 또렷하게 읽히도록 자간을 벌린다 |

제목 칸의 좌우 안여백은 `50px` 로 넉넉히 준다. 글자 길이와 무관하게 탭처럼 보이게 하기 위함이다.

```html
<div class="note">
  <b>법인등록번호 대조 상대의 부재</b>   <!-- 테두리에 걸치는 제목 칸. <p> 밖에 둔다 -->
  <p>현재 … 컬럼이 존재하지 않는다.</p>
</div>
```

`<b>` 를 `<p>` 안에 넣으면 제목 칸이 생기지 않고 굵은 글씨로만 보인다. 표나 도식을 상자 안에 넣을 때에도
`<p>` 와 나란히 `.note` 의 직계 자식으로 둔다.

### 제목 규칙

| 단계 | 규칙 | 예 |
|---|---|---|
| **H1** | 문서 제목 하나 | `Ⅰ. 과제 개요` |
| **H2** | 상위 절. 원 서식이 정한 **번호와 이름을 그대로** 쓴다. 서식에 없는 자체 절만 번호 없이 쓴다 | `1. 현안 및 문제정의` / `채워야 할 항목` |
| **H3** | 하위 항목. **`<H2번호>.<일련번호>. ` 로 시작하며, 문장이 아니라 명사구로 쓴다** | `3.1. 실증 대상 사업 및 기관` |
| **H4** | 하위 항목 안의 갈래. **`<H3번호>.<일련번호>. `** 로 시작한다. 갈래가 셋 이상일 때만 쓴다 | `3.1.1. 사업자등록증 JSON` |
| **H5** | 갈래 안의 세부. **`<H4번호>.<일련번호>. `** 로 시작한다. 네 단계가 꼭 필요할 때만 쓰고, 그 전에 절을 나눌 수 없는지 먼저 본다 | `3.1.1.1. 필수 항목 판정` |

H3 번호는 소속 H2 의 번호를 앞에 두고 점으로 잇는다. 3절의 첫 하위 항목은 `3.1.`, 두 번째는 `3.2.` 이다.
번호 뒤에는 마침표를 붙이고 공백을 둔다. `3.1. 최종 목표는 …`(O), `3.1 최종 목표는 …`(X).
H4 와 H5 도 같은 방식이다. 보이는 번호 `3.1.1.` 에 id `s3-1-1` 을, `3.1.1.1.` 에 `s3-1-1-1` 을 대응시킨다.
HTML 로 쓸 때 앵커 id 는 하이픈으로 `s3-1` 을 쓴다. 보이는 번호는 `3.1.`, id 는 `s3-1` 로 서로 대응시키고,
검증 스크립트가 둘의 대응을 검사한다. id 에 점을 쓰면 CSS 선택자에서 클래스 표기와 뒤섞이므로 쓰지 않는다.

제목 단계는 왼쪽 세로줄 색으로도 구분한다. H3 는 강조색(`--accent`), H4 는 초록색(`--good`), H5 는 주황색(`--warn`) 을 쓴다. H5 는 색만 다르고 글자 크기와 여백은 H4 와 같게 둔다.
글자 크기 차이만으로는 훑어볼 때 단계가 갈리지 않는다.

H3 를 문장으로 쓰지 않는다. `3.1. 본 실증의 최종 목표는 …이다`(X) → `3.1. 실증 대상 사업 및 기관`(O).
서술은 본문이 맡고 제목은 찾아가는 표지만 맡는다. 제목이 문장이면 목차가 길어져 사이드바에서 줄이 접힌다.
**목차에는 H5 까지 싣는다.** H2·H3·H4·H5 를 네 단계로 중첩하고, 깊이마다 들여쓰기와 글자 크기를 줄인다.
**목차의 하위 항목과 본문 제목은 글자 하나까지 같게 쓴다.** 목차 폭에 맞추어 라벨을 정하고 그것을 본문 제목으로 그대로 쓴다.
둘이 다르면 목차에서 찾은 항목을 본문에서 알아보지 못한다. 검증 스크립트가 둘의 일치를 검사한다.
목차를 `<ol>` 로 감쌀 때에는 CSS 에 `list-style:none` 을 두어 번호가 두 번 찍히지 않게 한다.

### 본문 구성 규칙

본문을 줄글 문단(`<p>`)으로 늘어놓지 않는다. 절 아래의 내용은 전부 목록 항목(`<li>`)으로 쓰고,
**들여쓰기 깊이로 계층을 나타낸다.** 읽는 사람이 어느 내용이 어느 내용에 딸린 것인지 눈으로 가릴 수 있어야 한다.

| 깊이 | 표지 | 무엇을 담는가 |
|---|---|---|
| 1단계 | `○` | 절을 이루는 주장 한 덩어리. 줄글에서 문단 하나에 해당한다 |
| 2단계 | `–` | 1단계 항목을 이루는 갈래 |
| 3단계 | `·` | 2단계 항목의 세부 |
| 순서 목록 | `1. 2. 3.` | 차례가 있는 절차. `<ol>` 로 쓰고 표지를 바꾸지 않는다 |

HTML 로 쓸 때에는 최상위 목록에 `class="outline"` 을 준다. 표지는 CSS 의 `::before` 로 넣고 `list-style:none` 을 둔다.

**들여쓰기는 목록(`ul`)이 아니라 항목(`li`)이 갖는다.** `ul` 은 `padding-left:0` 으로 두고, `li` 에 `padding-left` 를 준다.
표지는 `position:absolute; left:0` 으로 그 항목의 왼쪽 끝에 고정한다.

```css
ul.outline        { padding-left:0; }
ul.outline > li   { position:relative; padding-left:19px; }   /* 1단계 */
ul.outline > li::before { position:absolute; left:0; }
ul.outline ul > li      { position:relative; padding-left:17px; }  /* 2단계 이하 */
```

목록에 여백을 주는 흔한 방식으로도 화면 결과는 같다. 다만 그 방식은 표지를 `left:-19px` 처럼 음수로 끌어내야 해서
**목록의 여백과 표지의 위치가 항상 같은 숫자로 짝을 이뤄야 하고, 한쪽만 고치면 표지가 본문에서 떨어져 나간다.**
항목이 갖게 하면 기준점이 `li` 하나뿐이라 값을 바꿔도 표지가 따라온다. 단계가 여럿일수록 이 차이가 커진다.

**`<ol>` 만 예외로 목록이 여백을 갖는다**(`padding-left:24px`). 번호는 우리가 그리지 않고 브라우저가
`list-style-type:decimal` 로 붙이며, 그 번호가 놓일 자리는 목록이 마련해야 하기 때문이다.

**표·도식·주의 상자·캡션은 그 내용이 딸린 `<li>` 안에 넣어 함께 들여쓴다.** 절 바로 아래에 나란히 두면
어느 항목을 뒷받침하는 것인지 알 수 없다. H4 갈래와, 쓰는 경우의 작성 요령 상자(`.guide`)만 목록 밖에 둔다.

### 상호참조 규칙

본문에서 하위 항목을 가리킬 때에는 **H3 번호를 그대로 적는다.** `3.2.에 기술한`(O), 다른 장이면 `Ⅲ장 3.2.에 기술한`.
가리키는 대상이 절 전체이면 절 단위로 적는다. `3절에 기술한`(O).
"본 절 뒷부분", "위에서 설명한" 처럼 위치로 가리키지 않는다. 읽는 사람이 어디를 보아야 할지 알 수 없다.

H3 제목을 바꾸거나 번호 체계를 손댈 때에는 **본문의 상호참조가 함께 깨지므로 반드시 같이 고친다.**
확인 명령은 다음과 같다. 숫자 뒤에 조사가 붙은 것만 참조이고 `4.7배`·`3.75퍼센트` 같은 수치는 아니므로,
뽑아낸 번호가 실제로 존재하는 H3 인지 대조하여 없는 절을 가리키는 참조를 걸러낸다.

```bash
grep -oE '[0-9]{1,2}\.[0-9]\.?(에|의|에서|을|를|이|과|와| 참고)' <파일>
```

## CSS 작성 규칙

`<style>` 안은 **한 줄에 선언 하나**로 적는다. 선택자와 여는 중괄호가 한 줄, 선언이 한 줄씩, 닫는 중괄호가 한 줄이다.
여러 선택자를 묶은 규칙은 선택자도 한 줄에 하나씩 적는다.

```css
  .c1 td:nth-child(1),
  .c2 td:nth-child(2) {
    text-align:center;
  }
  @media (prefers-color-scheme: dark) {
    :root {
      --bg:#0d1117;
    }
  }
```

한 줄에 몰아 적으면 어느 값을 고쳐야 하는지 찾기 어렵고, 값 하나를 바꾼 변경 이력이 줄 전체로 잡힌다.
`@media` 안의 규칙은 한 단계 더 들여쓴다.

**색상값을 직접 적지 않는다.** `:root` 에 정의한 팔레트 변수(`--bg`, `--card`, `--line`, `--dim`, `--accent`,
`--warn`, `--good`, `--bad`)로만 쓴다. 이 서식은 밝은 화면과 어두운 화면 두 벌의 팔레트를 갖고 있어,
`#f7f9fb` 처럼 직접 적으면 어두운 화면에서 흰 상자가 남아 글자가 보이지 않는다.
중간색이 필요하면 `color-mix(in srgb, var(--accent) 12%, var(--bg))` 처럼 섞어 쓴다.

### 다시 정렬할 때의 함정

CSS 를 자동으로 다시 정렬하는 스크립트를 쓸 때에는 **주석 안의 쉼표에 주의한다.** 선택자 구분자로 오인되어
주석이 두 줄로 쪼개진다(2026-08-19 실제 발생). 규칙 위에 다는 주석에는 쉼표와 꺾쇠(`<`, `>`)를 쓰지 않는다.
꺾쇠는 HTML 태그 정합 검사까지 틀리게 만든다.

## 인쇄와 PDF 저장

보고서는 종이로 제출되거나 PDF 로 첨부되는 일이 많다. **화면용 서식을 그대로 인쇄하면 못 쓴다.**
서식 템플릿에 `@media print` 규칙이 들어 있으므로 그대로 두고, 새로 만들 때에도 지우지 않는다.

인쇄에서 반드시 달라져야 하는 것은 다음 네 가지이다.

| 무엇을 | 왜 |
|---|---|
| 좌측 목차를 숨기고 본문을 1단으로 편다 | 종이에는 고정 사이드바가 뜻이 없고, 본문 폭만 좁아진다 |
| 표의 `overflow-x:auto` 를 `visible` 로 풀고 `min-width` 를 없앤다 | **종이에는 가로 스크롤이 없어 넓은 표의 오른쪽이 잘려 나간다** |
| 표·도식·주의 상자에 `break-inside:avoid` 를 준다 | 상자 한가운데에서 쪽이 넘어가면 읽을 수 없다 |
| `print-color-adjust:exact` 를 준다 | 브라우저는 인쇄 시 배경색을 지운다. 표 머리글·강조 행·주의 상자의 구분이 전부 사라진다 |

함께 지정하는 것들은 다음과 같다.

- `@page { size:A4; margin:18mm 16mm 20mm; }` — 용지와 여백
- 본문 `10.5pt`, 표 `9pt` — 화면용 px 크기는 종이에서 지나치게 크다
- 제목에 `break-after:avoid` — 제목만 쪽 맨 아래 남는 것을 막는다
- `thead { display:table-header-group }` — 표가 여러 쪽에 걸치면 머리글 행을 쪽마다 반복한다
- `.cap { break-before:avoid }` — 캡션이 표와 떨어지지 않게 한다

### 확인 방법

고친 뒤에는 **화면이 아니라 인쇄 결과를 본다.** 헤드리스 브라우저로 PDF 를 뽑아 첫 두 쪽을 눈으로 확인한다.

```python
pg.emulate_media(media="print")          # 인쇄 스타일 적용
pg.pdf(path=OUT, format="A4", print_background=True)
```

사용자에게 안내할 때 한 가지를 반드시 덧붙인다. **인쇄 설정의 「배경 그래픽」을 켜야 음영과 색이 나온다.**
브라우저에 따라 기본값이 꺼져 있어, 켜지 않으면 표 머리글과 강조 행이 전부 흰색으로 나온다.

## When to skip

- 내부 개발 로그, 커밋 메시지, 코드 주석 — 대외 문서가 아니므로 적용하지 않는다
- 사용자와의 대화 응답 자체 — 이 스킬은 파일을 대상으로 한다
- 원문을 그대로 옮겨야 하는 인용 자료

## 문안 원칙 — 무엇을 쓰고 무엇을 쓰지 않는가

어투를 다듬기 전에 **무엇을 쓸 것인가**가 먼저 정해져야 한다. 아래는 실제 작업에서 사용자에게
제지받아 확정된 원칙이다.

### 1) 한 일을 보고하지 말고 기준을 적는다

지표에 맞추어 쓰라는 지시는 지표에 맞추었다고 보고하라는 뜻이 아니다.
제목과 본문에서 작성 경위("…에 연결하였다", "…에서 끌어왔다", "…에 따라 배정하였다")를 걷어내고,
참조한 문서와 지표는 문장 안에 녹인다. 기준은 **세어서 판정할 수 있는 조건문**으로 적는다.

- (X) 3.3 단계별 완료 기준을 Ⅰ장이 정한 최종 목표와 지표에 연결하였다
- (O) 3.3 단계마다 마일스톤과 완료 기준을 정하였다 → 표의 칸: `근거 확보율 95퍼센트 이상일 것`

### 2) 계획의 기준에는 목표값을 적고 달성값을 적지 않는다

실적이 99.4퍼센트여도 완료 기준은 **95퍼센트처럼 착수 시점에 세울 법한 값**으로 적는다.
달성값은 결과 장이 맡는 자리이므로 계획·추진 장에 옮겨 적으면 두 장의 역할이 겹친다.

- 목표값을 이미 다른 장이 선언했으면 **그 값을 그대로 인용**하여 문서 사이의 어긋남을 막는다.
- 선행 문서에 목표값이 없어 새로 정했다면 **어느 값을 새로 정했는지 사용자에게 밝힌다.**

### 3) 설명용 비유를 문서로 옮기지 않는다

대화에서 구조를 이해시키려고 만든 말은 제출물의 용어가 아니다.
문서에는 그 대상을 가리키는 실체어를 적는다. 금지된 표현은 `references/banned-terms.md` 에 누적한다.

### 4) 코드의 내부 명칭을 그대로 쓰지 않는다

seed·budget·pool·hop 처럼 구현이 쓰는 이름은 독자가 코드를 보지 않으므로 뜻이 전달되지 않는다.
우리말 실체어로 바꾸어 적고, 상수는 값까지 함께 적는다(예 "유사도 최고값에서 0.05 이내",
"지식 이웃이 100개를 넘는 용어는 경유하지 않는다").

### 5) 예시는 지어내지 말고 실측으로 만든다

도식과 표의 예시는 실제 시스템을 한 번 돌려 그 결과로 채운다. 캡션에 **측정일과 실측이라는 사실**을
밝히고, 지어낸 예시라면 그 사실도 밝힌다. 실행 자원이 부족하면(예 GPU 여유 부족) 모델을 새로
올리지 말고 **이미 떠 있는 서비스에 읽기 전용으로 질의**한다. 운영 중인 서비스를 재기동하지 않는다.

### 6) 모든 비율에 분모를 병기한다

분모가 작아지면 비율이 좋아 보인다. `근거 확보율 96.2퍼센트`가 아니라
`사실 주장 1,975건을 분모로 근거 확보율 96.2퍼센트`로 적는다.

## 표의 정렬과 수치 표기

머리글(`th`)은 언제나 가운데 정렬한다. 데이터 칸(`td`)은 **그 열에 담긴 값의 형식**에 따라 정한다.

| 정렬 | 대상 | 예 |
|---|---|---|
| 왼쪽 | 문장, 그리고 **쉼표로 구분된 여러 항목의 나열** | `BIZ_NM, BIZ_NO, FNDN_YMD` / `safechem 데이터와 일치하면 PASS` |
| 가운데 | 날짜, 그리고 **하나의 명칭** | `사업자등록증` / `2026-01-26` / `PASS` |
| 오른쪽 | 숫자 | `1,097건` / `3인` |

**띄어쓰기가 있다고 나열이 아니다.** 「4대 사회보험 가입자 명부」는 띄어 썼을 뿐 서류 하나의 이름이므로
가운데 정렬이다. 나열은 쉼표로 여러 항목이 이어진 것을 말한다. 이 둘을 혼동하면 명칭 열이 왼쪽으로 밀려
같은 성격의 열끼리 정렬이 어긋난다(2026-08-19 지적받아 시정).

정렬은 한 열 전체에 같게 준다. 한 열 안에서 칸마다 다르면 오히려 읽기 어렵다.
값이 섞여 있으면 그 열의 대표 형식을 하나 골라 통일한다.

### 정렬을 지정하는 방법

칸마다 클래스를 붙이지 않는다. **표에 열 번호 클래스를 주고 `nth-child` 로 열 단위로 건다.**

```html
<table class="c1 r2">   <!-- 1열 가운데, 2열 오른쪽. 나머지는 왼쪽(기본값) -->
```

```css
.c1 td:nth-child(1), .c2 td:nth-child(2), … { text-align:center; }
.r1 td:nth-child(1), .r2 td:nth-child(2), … { text-align:right; font-variant-numeric:tabular-nums; }
```

칸마다 붙이면 행을 하나 추가할 때마다 클래스를 빠뜨리게 되고, 열의 정렬을 바꾸려면 모든 칸을 고쳐야 한다.
오른쪽 정렬에는 `font-variant-numeric:tabular-nums` 를 함께 주어 자릿수가 세로로 맞게 한다.

### 수치 표기

**수량과 금액은 천 단위마다 쉼표를 찍는다.** `1097건`(X) → `1,097건`(O).

다만 다음은 쉼표를 찍지 않는다. 자릿수를 세는 값이 아니라 하나의 식별 기호이기 때문이다.

- 식별번호 — 사업자등록번호, 법인등록번호, 관리번호, 발급번호
- 연도와 날짜 — `2026`, `2026-01-26`, 파일명의 `20260126`
- 판(version)·조문 번호

## 표와 도식의 문안 형식

- **표 칸은 「요약 문장 한 줄 + ①②③④ 절차 항목」으로 통일한다.** 산문 서술을 절차 단위로 쪼개면
  같은 정보가 더 짧아지고 칸끼리 비교된다. 항목 수가 부족하면 억지로 만들지 말고 원문에 이미 있는
  조건을 풀어 적는다. 구분자 기호는 문서 안에서 한 가지로 통일한다.
- **세로로 쌓거나 되돌아오는 그림은 `.flow` 로 그리지 않는다.** 한글이 고정폭 글꼴에서 두 배 폭이라
  줄마다 폭이 달라져 정렬이 깨진다(실측: 같은 상자가 65칸과 66칸으로 섞임). `.fig` 안 SVG 로 그린다.
- 한 줄에 상자를 늘어놓을 때는 `상자 폭 × 개수 + 간격 × (개수−1)` 이 viewBox 안쪽 폭과 맞는지
  먼저 계산한다. 상자 안 글자는 한글 1자 ≒ 글꼴 크기, 숫자·영문 ≒ 글꼴 크기의 0.55 로 어림한다.
- **화살표가 서로 교차하면 안 된다.** 두 경로가 같은 여백을 지나가면 하나를 없애거나, 감싸는 띠로
  바꾸어 화살표 자체를 제거한다.
- 그림 안에서 호출 관계를 보일 때는 점선 상자로 감싸고, 드나드는 지점에 굵은 화살표와 이름을 붙인다
  (예 "선언서를 전달한다" / "근거 노드를 받는다").

## 판정 흐름도 그리는 법

여러 항목이 각각 다른 기준으로 판정되고 그 결과가 하나로 모이는 구조는 표로는 관계가 드러나지 않는다.
**레인 구조**로 그린다. 항목 하나가 가로 한 줄을 차지하고, 오른쪽 끝의 키 큰 상자가 모든 줄을 받는다.

```
[항목]  →  [무엇과 대조하는가]  ────────→  ┌──────────┐
[항목]  →  [무엇과 대조하는가]  ────────→  │  결과    │
[항목]  →  [무엇과 대조하는가]  ┈┈┈┈┈┈┈▶  │  상자    │
                                          └──────────┘
```

### 선과 상자로 뜻을 가른다

글로 "이건 반영되고 저건 안 된다"고 적지 말고 **모양으로 보이게 한다.** 서식이 제공하는 class 를 쓴다.

| 뜻 | 선 | 상자 |
|---|---|---|
| 결과를 결정하는 경로 | `.ln-a` 실선(강조색) | `.box-term` (강조색 테두리·옅은 채움) |
| 결정하지 않는 경로 | `.ln` + `stroke-dasharray="4 3"` (점선·회색) | `.box` (무채색) |
| 불합격으로 가는 경로 | `.ln-f` 실선(붉은색) | `.box-fact` (붉은 테두리) |
| 입력·원본 | `.ln` 실선(회색) | `.box-src` |

글자도 같은 규칙을 따른다. `.t-a` 강조, `.t-f` 붉은색, `.t-d` 보조, `.t-b` 굵게.

### 조건은 마름모로 그린다

「예/아니오」로 갈리는 곳은 `<polygon>` 마름모를 쓴다. 중심 (cx, cy) 에서 가로 반폭 46, 세로 반높이 26 이면
「일치?」 정도의 짧은 물음이 들어간다.

```html
<polygon class="box" points="368,208 414,234 368,260 322,234"/>
<text class="t-b" x="368" y="239" text-anchor="middle">일치?</text>
```

**갈래마다 「예」·「아니오」를 반드시 붙인다.** 붙이지 않으면 어느 쪽이 어느 조건인지 읽는 사람이 알 수 없다.
두 경로가 같은 결과로 합류하면 **같은 상자로 화살표를 모은다.** 그것이 "어느 경로로 통과하든 결과는 하나"라는
사실을 보이는 방법이다.

### 한 판정을 이루는 구간은 점선 상자로 묶는다

두 항목이 별개가 아니라 하나의 판정을 이룰 때에는 점선 테두리로 감싸고 제목을 붙인다.

```html
<rect class="box" x="4" y="200" width="600" height="196" rx="10" stroke-dasharray="5 4" fill="none"/>
<text class="t-a" x="8" y="192">기업 식별번호 판정 &#8212; BIZ_NO 가 불일치할 때에만 CORP_NO 를 본다</text>
```

제목은 상자 **위쪽 바깥**에 둔다. 상자 안에 넣으면 첫 줄 내용과 겹친다.
제목 기준선과 그 위 요소의 아래변 사이는 20px 이상 벌린다(실측: 8px 로 두었다가 겹쳤다).

### 좌표를 잡는 순서

1. viewBox 너비는 760 으로 고정한다. 본문 폭에 맞춰 둔 값이다.
2. 레인 높이 40, 간격 10(pitch 50)을 기본으로 잡고 줄 수만큼 곱해 전체 높이를 낸다.
3. 각 열의 x 와 폭을 먼저 정하고, 화살표는 상자 사이 빈 구간에만 그린다.
4. 글자 폭은 **한글 1자 ≒ 글꼴 크기, 영문·숫자 ≒ 글꼴 크기의 0.55** 로 어림해 상자 폭과 비교한다.
5. 결과 상자는 첫 레인 위쪽부터 마지막 레인 아래쪽까지 한 덩어리로 세운다. 레인마다 결과 상자를
   따로 두면 "여러 항목이 하나로 모인다"는 뜻이 사라진다.

### 그린 뒤 반드시 좌표로 검사한다

눈으로만 보면 겹침을 놓친다. 브라우저에 띄워 **글자 겹침과 상자 넘침을 좌표로** 확인한다.

```python
pg.evaluate("""()=>{
  const svg=document.querySelector('svg[aria-label^="찾을 라벨"]');
  const bad=[];
  // 글자끼리 겹침
  const ts=[...svg.querySelectorAll('text')].map(t=>({t:t.textContent.slice(0,16),b:t.getBBox()}));
  for(let i=0;i<ts.length;i++)for(let j=i+1;j<ts.length;j++){
    const a=ts[i].b,c=ts[j].b;
    if(a.x<c.x+c.width&&c.x<a.x+a.width&&a.y<c.y+c.height&&c.y<a.y+a.height)
      bad.push('겹침: '+ts[i].t+' / '+ts[j].t);}
  // 상자 밖으로 넘친 글자
  const rs=[...svg.querySelectorAll('rect')].map(r=>({x:+r.getAttribute('x'),w:+r.getAttribute('width'),
                                                      y:+r.getAttribute('y'),h:+r.getAttribute('height')}));
  svg.querySelectorAll('text').forEach(t=>{const b=t.getBBox();
    if(t.getAttribute('text-anchor')!=='middle') return;
    const h=rs.find(r=>b.y>=r.y-2&&b.y<=r.y+r.h+2&&b.x+b.width>r.x-2&&b.x<r.x+r.w+2&&r.w<560);
    if(h&&(b.x<h.x+2||b.x+b.width>h.x+h.w-2)) bad.push('넘침: '+t.textContent.slice(0,20));});
  return bad;}""")
```

0건이 나온 뒤 캡처해서 눈으로 한 번 더 본다. 화살표 교차는 좌표로 잡히지 않으므로 이때 확인한다.

### 대체 텍스트

`role="img"` 와 `aria-label` 을 반드시 붙인다. **그림을 못 보는 사람이 라벨만 읽고 결론에 이를 수 있어야 한다.**
"무엇을 그린 그림"이 아니라 "무엇이 어떻게 되는지"를 적는다.
(X) 판정 흐름도 → (O) 사업자등록번호가 불일치할 때에만 법인등록번호를 대조하고, 둘 중 하나라도 일치하면 PASS 로 확정한다

## 번호 체계와 구조를 바꿀 때

과업 번호·절 번호·과업군 이름을 바꾸면 **문서 전체가 함께 깨진다.** 먼저 파급 지점을 세어 두고 일괄로 고친다.

```bash
grep -nE 'T([1-9]|1[0-9])\b|열[한두세네다]* 개 과업|#s[0-9-]+' <파일>
```

| 파급 지점 | 확인 방법 |
|---|---|
| 도식의 상자 라벨과 `aria-label` | `<text` 와 `role="img"` 를 함께 본다. 대체 텍스트를 빠뜨리기 쉽다 |
| 간트 차트·마일스톤 표의 과업 배정 | 단계별 과업 나열 칸 |
| 역할 분담표의 담당 과업 범위 | `T1~T11` 같은 범위 표기 |
| 과업 총수 표기 | "열한 개 과업" 이 제목·본문·도식·2절·3절에 흩어져 있다 |
| 본문 상호참조 | "그 절차는 과업 T8에 기술한다" |
| 목차 라벨 | 절 제목을 바꾸면 목차도 바꾼다 |
| **다른 장의 대응 문장** | 예 Ⅰ장 "세 하위 목표는 Ⅱ장의 과업군 A·B·C에 대응한다" — 고칠 수 없으면 사용자에게 보고한다 |

치환은 **원문이 정확히 한 번 일치할 때만 바꾸고 하나라도 어긋나면 중단하는** 스크립트로 한다.
일부만 적용되고 넘어가면 번호가 뒤섞인 문서가 남는다.

## 절을 통째로 지울 때

- 서식이 요구하는 항목을 지우면 작성 요령 상자만 남고 그 요구를 채우는 내용이 사라진다.
  지우되 **"이 절의 서식 요구가 지금 비어 있다"는 사실을 사용자에게 알린다.**
- 지운 절에만 있던 수치는 문서에서 사라진다. **어떤 수치가 사라졌는지 목록으로 보고한다.**
- 자리표시자(`.fill`)가 사라지면 문서 끝 「채워야 할 항목」 표의 해당 행도 함께 고친다.

## 정규화 8규칙

| 규칙 | 대상 | 변환 방향 | 예 |
|---|---|---|---|
| **R1** | 접속·전환어의 격식화 | 구어 접속부사를 문어 접속부사로 | 그런데→그러나, 그래서→따라서, 하지만→그러나, 다시 말해→즉, 반면→다만 |
| **R2** | 고유어·비유 술어의 한자어화 | 일상어·비유 동사를 한자어 술어로 | 넘어선다→초과한다·이상이다, 만들다→구축·생성·작성한다, 올랐다→상승하였다, 잃는다→소실된다, 훑다→순회한다 |
| **R3** | 고유어 의존명사의 한자어화 | 수량 한정 표현을 한자어로 | 가운데→중, 그 가운데→그 중 |
| **R4** | 양보·조건 어미의 명사구화 | 구어 연결어미를 명사구로 | ~하더라도→~의 경우, ~이라도→~의 경우에도 |
| **R5** | 지시어의 명사 재지칭 | 대명사·지시관형사를 명사로 | 이 한 권→위 원문문서, 그것→해당 원문, 여기에→이에 |
| **R6** | 구어 부사·완곡 표현의 제거 | 군더더기 부사를 삭제하거나 대체 | 애초에→당초, 아예→자체가, 사실상→실질적으로, 마땅치 않다→확보되어 있지 않다 |
| **R7** | 부정 표현의 통일 | 문서 내 혼재를 한쪽으로 일치 | ~하지 아니한다→~하지 않는다 |
| **R8** | 의문형 제목의 명사구화 | 소제목을 명사구로 | 왜 ~인가→~의 불가피성, 실제로 쓰이는가→실제 활용도 |

R5는 프로젝트 지침(CLAUDE.md 7항 "대명사를 쓰지 말고 명사로 지칭")과 동일한 요구이다.

**R7의 방향은 '않다' 계열로 확정되어 있다**(2026-08-13 사용자 지시).
'아니하다'는 법령 문체여서 과도하게 딱딱하므로 '않다'로 통일한다.
다만 다음 두 가지는 R7의 대상이 아니므로 절대 건드리지 않는다.

- 형용사 **'아니다'** — `A가 아니라 B`, `~이 아니면`. 보조용언 '아니하다'와 다른 낱말이다.
- 금지 표현 **'~하여서는 아니 된다'** — 규범 문서의 관용 표현이므로 그대로 둔다.

그래서 규칙표의 R7 원문은 반드시 `아니하`·`아니한`·`아니할`·`아니함` 으로 시작하는 형태로만 잡는다.
`아니`만으로 잡으면 위 두 가지가 함께 망가진다.

## 절대 치환하면 안 되는 구간

치환 대상에서 **반드시 제외**한다. 스크립트가 자동으로 가려 두지만, 새 유형이 나오면 스크립트에 추가한다.

| 구간 | 사유 | 탐지 방법 |
|---|---|---|
| 주최 측 서식이 정한 작성 요령·심사 기준 | 원문을 임의로 고치면 서식 위반 | HTML `<div class="guide">`, 마크다운 `>` 인용 |
| 법령·표준·타 기관 문서의 인용문 | 인용의 정확성이 훼손됨 | 큰따옴표 안, 인용 블록 |
| 코드·파일 경로·모델명·명령어 | 실행 불가능해짐 | HTML `<code>`·`<pre>`, 마크다운 백틱·펜스 |
| 스타일시트·스크립트 | 문서 내용이 아님 | HTML `<style>`·`<script>` |
| 표 안의 실제 질문 목록 | 의문형이 내용상 맞는 경우 | 사람이 판단하여 규칙에서 제외 |

## 절차

### 0) 금지 용어 점검 — 대장에 오른 말이 남아 있는지 본다

```bash
grep -nE '씨앗|큰 흐름|작은 흐름|예산' "<대상 경로>"
```

`references/banned-terms.md` 의 표현이 하나라도 남아 있으면 먼저 문장을 다시 쓴다.
자동 치환하지 않는다 — 문맥마다 대체 표기가 다르다.

### 1) 스캔 — 후보를 찾는다

```bash
python3 .claude/skills/formalize-report/scripts/formalize.py --scan "<대상 경로 glob>"
```

구어체 후보 표현과 그 출현 횟수, 앞뒤 문맥을 출력한다.
**출력을 그대로 믿지 말 것.** 부분 문자열 오탐이 있다(예: "참여기관"에 "여기"가 포함됨).
반드시 문맥을 읽고 실제 교정 대상인지 판정한다.

### 2) 규칙표 확정 — 문맥을 보고 치환 쌍을 정한다

`references/rules.tsv` 에 `규칙ID<TAB>원문<TAB>대체문<TAB>범위` 형식으로 추가한다.

- **범위 `common`** — 문맥과 무관하게 항상 성립하는 치환. 예: `가운데` → `중`
- **범위 `context`** — 특정 문장에서만 성립하는 치환. 원문을 충분히 길게 잡아 오적용을 막는다

한 글자짜리 문자열을 `common`으로 넣으면 다른 낱말을 깨뜨린다. 두 글자여도 조사에 걸릴 수 있으면 앞뒤 공백을 함께 넣는다.
확신이 서지 않으면 원문을 문장 단위로 길게 잡아 `context`로 넣는다.

**규칙 순서가 중요하다.** 긴 문자열을 먼저 두어야 짧은 규칙이 먼저 소비하는 일이 없다.
R5(문장 단위 재작성)를 R3(낱말 치환)보다 앞에 배치한다.

### 3) 시험 적용 — 반드시 먼저 실행한다

```bash
python3 .claude/skills/formalize-report/scripts/formalize.py --dry "<대상 경로 glob>"
```

파일을 고치지 않고 치환 목록만 출력한다.
**목록을 한 줄씩 읽어 의미가 어긋나는 항목이 없는지 확인한 뒤에** 다음 단계로 간다.

### 4) 적용

```bash
python3 .claude/skills/formalize-report/scripts/formalize.py --apply "<대상 경로 glob>"
```

원본은 `--backup <디렉토리>` 로 보관한다. 기본값은 적용 전 백업을 만들지 않으므로,
git으로 관리되지 않는 문서라면 백업 경로를 반드시 지정한다.

### 5) 검증 — 여섯 가지를 전부 확인한다

```bash
python3 .claude/skills/formalize-report/scripts/formalize.py --verify "<대상 경로 glob>" --baseline <백업 디렉토리>
```

| 검사 | 통과 기준 |
|---|---|
| 잔여 구어체 | 스캔 목록의 표현이 0건일 것. 남았다면 규칙표에 추가하고 2)로 돌아간다 |
| 금지 용어 | `references/banned-terms.md` 의 표현이 0건일 것 |
| 태그 정합 | HTML 여는 태그와 닫는 태그의 수가 일치할 것 |
| 보호 구간 보존 | 백업본과 대조하여 인용문·코드 블록이 한 글자도 바뀌지 않았을 것 |
| 지시 문장 반영 | 사용자가 직접 지정한 문장이 지시대로 바뀌었을 것 |
| **기록 후 재읽기** | **파일을 다시 읽어 방금 쓴 내용이 실제로 남아 있을 것**(아래 참조) |

#### 기록 후 재읽기를 건너뛰면 안 되는 이유

**스크립트의 "완료" 출력은 반영의 근거가 아니다.** 사용자가 편집기로 같은 파일을 열어 두면
그 탭의 옛 버퍼가 저장되면서 방금 기록한 내용을 덮어 되돌린다. 2026-08-15 작업에서 이 일이
**두 번** 일어났고, 두 번 다 "적용했다"고 보고한 뒤 사용자가 "안 바뀌었다"고 지적하여 드러났다.

그러므로 기록한 뒤에는 파일을 **다시 읽어** 다음을 확인한다.

```python
open(P, 'w', encoding='utf-8').write(src)
back = open(P, encoding='utf-8').read()          # 반드시 다시 읽는다
assert '바꾼 뒤 문장' in back and '바꾸기 전 문장' not in back
```

되돌아가 있으면 다시 적용하고, **사용자에게 편집기 탭을 닫거나 `File: Revert File` 하도록 알린다.**
알리지 않으면 같은 일이 계속 반복된다.

### 6) 보고 — 사용자에게 무엇을 바꿨는지 알린다

- 적용한 규칙과 건수를 규칙별로 집계하여 제시한다
- 판단이 갈릴 수 있는 치환은 별도로 짚고 되돌릴 의사를 묻는다
  (예: R7을 어느 쪽으로 통일했는지, 의문형 제목을 어디까지 바꿨는지)
- 규칙표에 새로 추가한 항목이 있으면 그 사실을 밝힌다

## 자주 발생하는 사고

| 사고 | 원인 | 예방 |
|---|---|---|
| 파이프가 끊겨 일부 파일만 적용됨 | `--apply` 출력을 `head`로 잘라 `BrokenPipeError` 발생 | 출력을 파일로 리다이렉트한 뒤 읽는다 |
| 서식 원문이 훼손됨 | 보호 구간 지정 누락 | 적용 후 반드시 `--verify` 로 백업본과 대조한다 |
| 다른 낱말이 깨짐 | 짧은 문자열을 `common`으로 등록 | 한 글자 문자열은 `common` 금지 |
| 문장이 어색해짐 | 고유어 술어를 무차별 한자어화 | R2는 비유·일상어에만 적용하고, 이미 자연스러운 술어는 그대로 둔다 |
| 어미가 뒤엉킴 | 짧은 어미 규칙이 긴 어미보다 앞에 옴 | 규칙표를 어미 길이 내림차순으로 정렬 |
| 그림의 선과 상자가 어긋남 | `.flow` 로 좌우 배치·되돌아오는 선을 그림. 한글은 고정폭 글꼴에서 두 배 폭이라 줄마다 폭이 달라진다 | 오른쪽 정렬이 필요한 그림은 `.fig` 안에 SVG 로 그린다. `.flow` 는 왼쪽에서 오른쪽으로만 흐르는 그림에만 쓴다 |
| 고쳤다고 보고했는데 파일은 그대로임 | 사용자가 편집기로 연 탭의 옛 버퍼가 저장되며 덮어씀 | 기록 후 반드시 다시 읽어 확인하고, 사용자에게 탭을 닫도록 알린다 |
| 번호를 바꾼 뒤 문서가 뒤섞임 | 치환이 일부만 적용되었는데 넘어감 | 원문 1회 일치를 강제하고 하나라도 어긋나면 중단하는 스크립트로 치환한다 |
| 심사자가 서식 요구를 못 채웠다고 볼 수 있음 | 절을 지우면서 작성 요령 상자만 남김 | 지운 사실과 비게 된 요구를 사용자에게 보고한다 |
| 계획 문서에 달성값이 적힘 | 실측값을 완료 기준 칸에 그대로 옮김 | 완료 기준은 목표값으로 적고 달성값은 결과 장에 둔다 |
| 도식·표가 통째로 뭉개짐 | 다른 문서에서 블록을 옮겨 오면서 그 class 의 CSS 를 함께 옮기지 않음. `.flow` 가 없으면 `white-space:pre` 가 걸리지 않아 줄바꿈과 공백이 전부 사라진다 | 블록을 옮긴 뒤 `--verify` 의 **class 와 CSS 정의의 일치** 검사를 확인한다. 문서마다 CSS 가 다르므로 "다른 문서에 있으니 괜찮겠지"는 통하지 않는다 |

## 산출물 점검표

보고서를 완성했다고 보고하기 전에 다음을 전부 확인한다.

- [ ] 본문이 쓰는 class 가 **그 문서의** `<style>` 안에 전부 정의되어 있는가
- [ ] `<style>` 이 한 줄에 선언 하나로 정렬되어 있고, 색상값을 직접 적은 곳이 없는가
- [ ] H2 가 원 서식의 번호·이름과 일치하는가
- [ ] `.guide` 블록을 넣었다면 주최 측 서식이 그 요령을 실제로 요구한 것인가 (요구가 없으면 넣지 않는다)
- [ ] H3 가 전부 `<H2번호>.<일련번호>. ` 로 시작하고 문장이 아닌 명사구인가
- [ ] H3 제목이 목차의 같은 항목 라벨과 완전히 일치하는가
- [ ] H4 와 H5 가 번호와 id 를 갖고(`s3-1-1` ↔ `3.1.1.`, `s3-1-1-1` ↔ `3.1.1.1.`) 목차에 각각 3단계·4단계로 실려 있는가
- [ ] H3 번호가 앵커 id 와 대응하는가 (`s3-1` ↔ `3.1.`)
- [ ] 본문의 상호참조가 실제로 존재하는 절·항목을 가리키는가 (`3.2.에`의 3.2 가 실재하는가)
- [ ] 본문에 목록 밖 `<p>` 가 남아 있지 않은가 (캡션 `p.cap` 은 예외)
- [ ] 표·도식·주의 상자가 딸린 `<li>` 안에 들어가 있는가
- [ ] 모든 비율 수치에 분모가 병기되어 있는가
- [ ] 표·수치 카드에 측정 일자와 조건을 밝힌 캡션이 붙어 있는가
- [ ] 채우지 못한 항목이 `.fill` 로 표시되고 문서 끝 표에 모여 있는가
- [ ] 지어낸 수치가 없는가 — 확인하지 않은 외부 통계는 자리표시자로 남긴다
- [ ] `references/banned-terms.md` 의 금지 용어가 0건인가
- [ ] 작성 경위를 보고하는 문장("…에 연결하였다", "…에서 끌어왔다")이 없는가
- [ ] 계획·추진 장의 완료 기준이 달성값이 아니라 목표값인가
- [ ] 도식의 예시가 실측인가, 지어낸 예시라면 캡션에 그 사실이 적혀 있는가
- [ ] 도식의 글자 겹침·상자 넘침을 좌표로 검사하여 0건이고, 화살표가 교차하지 않는가
- [ ] 과업·절 번호를 바꾸었다면 도식·간트·역할표·총수 표기·상호참조·목차·다른 장이 모두 맞는가
- [ ] **기록한 뒤 파일을 다시 읽어 반영을 확인하였는가**
- [ ] 인쇄 결과를 PDF 로 뽑아 목차가 숨겨지고 표가 잘리지 않았는지 확인하였는가
- [ ] `--verify` 가 통과하는가

## 규칙표의 누적 관리

`references/rules.tsv` 는 **버리지 않고 계속 쌓는다.**
`common` 규칙은 다음 문서에서도 그대로 재사용되고, `context` 규칙은 해당 문서에만 걸린다.
새 문서를 정규화할 때마다 스캔에서 새로 나온 표현을 규칙표에 추가하여 다음 작업의 초기 적중률을 높인다.
